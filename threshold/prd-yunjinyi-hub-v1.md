## 1. 개요

### 1.1 제품 정의

`YunJin Yi® — HUB`는 이윤진의 개인 프로젝트 아카이브이자 온라인 명함이다.
지금까지 만든 것과 앞으로 만들 것을 한 곳에 누적하고, 채용 담당자에게 링크 하나로 전달할 수 있는 단일 진입점 역할을 한다.

### 1.2 목표

1. 채용 담당자가 **3분 안에** 지원자의 역량을 판단할 수 있게 한다.
2. 프로젝트를 **추가하는 비용을 최소화**해 아카이브가 실제로 계속 쌓이게 한다.
3. 첫 화면에서 **제작 역량 자체를 증명**한다 — 배경 셰이더가 곧 포트폴리오의 일부다.

### 1.3 성공 기준

- 신규 프로젝트 1건 추가에 필요한 작업이 **JSON 객체 하나 추가**로 끝난다.
- 채용 담당자가 프로젝트 상세까지 도달하는 데 **클릭 2회 이내**.
- 특정 프로젝트를 **URL 하나로 공유**할 수 있다.
- 저사양 기기·모션 민감 사용자에게도 **콘텐츠 접근이 차단되지 않는다**.

---

## 2. 타겟 사용자

### 2.1 주 타겟 — 채용 담당자

실제로는 두 명의 독자가 순차적으로 읽는다. 설계는 이 차이를 반영한다.

| 독자 | 행동 | 필요한 것 |
|---|---|---|
| **리크루터** (1차 스크리닝) | 빠르게 훑고 넘김 | 이름, 직함, 무엇을 만드는 사람인지, 연락처 |
| **현업 팀장·실무자** (2차) | 상세를 실제로 읽음 | 본인 기여도, 의사결정 근거, 결과, 검증 링크 |

리크루터를 위해 **리스트가 빠르게 스캔되어야** 하고, 실무자를 위해 **모달이 깊이를 가져야** 한다.

### 2.2 설계 원칙

> 실무자가 확인하려는 건 단 하나다 — "이 사람이 우리 팀에 왔을 때 혼자 굴러갈 수 있나."

모든 콘텐츠는 이 질문에 답하는지를 기준으로 넣고 뺀다.

## 3. 정보 구조

```
인트로 (#)
  └ [ENTER] ─────────────┐
                         ▼
프로젝트 리스트 (#/projects)
  ├ 프로젝트 카드 클릭 → 프로젝트 모달 (#/project/{slug})
  └ 상단 [CARD] 버튼   → 명함 모달 (#/card)
```

**단일 HTML 파일**로 구현하며, 화면 전환은 해시 라우팅으로 처리한다.

## 4. 화면별 요구사항

### 4.1 인트로 화면

풀스크린 WebGL 배경 위에 워드마크와 진입 버튼만 놓는다.

**구성 요소**

| 요소 | 내용 | 비고 |
|---|---|---|
| 워드마크 | `YunJin Yi®` (상단) / `HUB` (하단) | 모노스페이스 대문자 |
| 진입 버튼 | `ENTER` | 중앙 하단 |
| 로딩 표시 | 퍼센트 또는 진행 바 | 셰이더 초기화 완료 전까지 |

**요구사항**

- `ENTER` 클릭 시 리스트로 전환. 전환 중 디더링 배경은 유지하되 왜곡 강도를 일시적으로 증폭했다가 감쇠시켜 연결감을 준다.
- **스킵 경로 (필수)** — 채용 담당자의 이탈을 막기 위한 장치다.
  - `#/projects`로 직접 진입하면 인트로를 건너뛴다.
  - 재방문 시(`sessionStorage` 플래그) 인트로를 자동 생략한다.
  - 인트로에서 5초 이상 머물면 `SKIP` 힌트를 노출한다.

### 4.2 프로젝트 리스트

**구성 요소**

- 상단 바 — 워드마크(축소), `CARD` 버튼
- 프로젝트 카드 그리드
- 하단 — 저작권 표기

**카드에 표시할 정보**

| 항목 | 필수 | 설명 |
|---|---|---|
| 커버 이미지 | ○ | 없으면 디더링 처리된 플레이스홀더 자동 생성 |
| 제목 | ○ | |
| 한 줄 설명 | ○ | 무엇을 만든 것인지 |
| 연도 | ○ | |
| 역할 배지 | ○ | `개인` / `팀` 구분 |
| 상태 배지 | △ | `진행 중` / `습작` 인 경우에만 |
| 기술 태그 | ○ | 최대 4개까지 노출 |

**요구사항**

- 프로젝트 수가 적을 때도 빈약해 보이지 않도록, 3개 미만이면 카드 크기를 키우는 레이아웃을 적용한다.
- 카드 호버 시 배경 왜곡이 해당 카드 영역에 반응한다.
- 리스트 자체는 스캔이 목적이므로 **읽는 부담을 늘리는 요소를 넣지 않는다.**

### 4.3 프로젝트 모달

**분량 기준: 프로젝트당 300~500자 + 이미지 2~3장.**
이 상한은 의도적이다. 분량이 부담되면 프로젝트를 안 올리게 되고, 그러면 아카이브라는 목적 자체가 무너진다.

**구성 항목 (순서 그대로)**

| 순서 | 항목 | 필수 | 작성 지침 |
|---|---|---|---|
| 1 | 제목 + 한 줄 설명 | ○ | |
| 2 | **역할** | ○ | 팀 프로젝트는 본인 담당 파트를 명시. 개인 작업은 "개인 프로젝트"로 표기 |
| 3 | 기간 | ○ | |
| 4 | 사용 기술 | ○ | |
| 5 | **문제와 해결** | ○ | 2~3문단. 무엇이 문제였고 어떻게 풀었는지 |
| 6 | **의사결정 근거** | ○ | 1~2개. 대안을 두고 골랐다는 증거 |
| 7 | 시행착오 | △ | **한 줄.** 길어지면 읽히지 않는다 |
| 8 | 결과 | ○ | 숫자가 있으면 숫자로, 없으면 정성적으로. 지어내지 않는다 |
| 9 | 이미지 | ○ | 2~3장 |
| 10 | **외부 링크** | ○ | 라이브 URL / 깃허브 / 영상. 이게 없으면 위 내용이 전부 주장으로만 남는다 |

**작성 시 피해야 할 것**

- ✗ "우리는 ~했다" — 팀 프로젝트에서 기여도가 0으로 읽힌다
- ✗ 결과 수치를 추정으로 채우기
- ✗ 시행착오를 여러 문단으로 늘리기

**동작 요구사항**

- 모달 열림 시 URL 해시를 `#/project/{slug}`로 갱신한다.
- 해당 해시로 직접 진입하면 리스트 위에 모달이 열린 상태로 렌더링한다.
- 브라우저 뒤로가기로 모달이 닫힌다.
- `ESC` 키, 배경 클릭으로도 닫힌다.
- 모달 열림 중 배경 스크롤을 잠근다.
- 포커스를 모달 내부에 가둔다 (focus trap).

### 4.4 명함 모달

상단 `CARD` 버튼으로 열며, 프로젝트 모달과 동일한 인터랙션 규칙을 따른다. 해시는 `#/card`.

**구성 항목**

- 이름 — `이윤진 / YunJin Yi`
- 직함 / 한 줄 소개
- 이메일 (클릭 시 메일 앱 연결)
- 외부 링크 — 깃허브, 링크드인 등
- 이력서 파일 링크 (선택)

**요구사항**

- 이메일 주소는 **평문으로 노출하지 않는다.** 스팸 수집 봇 방지를 위해 스크립트로 조합해 렌더링한다.
- vCard(.vcf) 다운로드 버튼은 선택 사항으로 둔다.

## 5. 데이터 구조

프로젝트는 HTML 내 `<script type="application/json">` 블록에 배열로 보관한다.
**프로젝트 추가 시 이 배열에 객체 하나만 넣으면 되며, 그 외 코드는 수정하지 않는다.**

```json
{
  "slug": "dithering-hub",
  "title": "프로젝트 제목",
  "summary": "한 줄 설명",
  "year": "2026",
  "period": "2026.03 – 2026.05",
  "type": "personal",
  "status": "published",
  "role": "기획, 디자인, 프론트엔드 전체",
  "stack": ["WebGL2", "GLSL", "TypeScript"],
  "cover": "assets/cover.jpg",
  "images": ["assets/01.jpg", "assets/02.jpg"],
  "problem": "무엇이 문제였는지, 어떻게 풀었는지 (2~3문단)",
  "decisions": [
    "Three.js 대신 순수 WebGL2를 선택 — 단일 파일 배포가 요구사항이었기 때문"
  ],
  "learning": "처음엔 A로 했다가 B 때문에 갈아엎었다 (한 줄)",
  "result": "결과 서술",
  "links": [
    { "label": "Live", "url": "https://..." },
    { "label": "GitHub", "url": "https://..." }
  ]
}
```

**필드 규칙**

| 필드 | 값 |
|---|---|
| `type` | `personal` \| `team` |
| `status` | `published` \| `wip` \| `study` |
| `slug` | URL에 쓰이므로 영문 소문자 + 하이픈만 |
| `images` | 비어 있으면 커버만 표시 |
| `learning` | 비어 있으면 해당 섹션 자체를 렌더링하지 않음 |

## 6. 기술 요구사항

### 6.1 제약

- **단일 HTML 파일.** 빌드 도구, 번들러, 외부 라이브러리 없음.
- **순수 WebGL2 + GLSL.** Three.js를 쓰지 않는다 — 풀스크린 quad와 FBO 핑퐁이 전부라 라이브러리가 하는 일이 없고, CDN 의존성만 생긴다.
- 파일 하나를 어디에 올려도 동작해야 한다.

### 6.2 배경 셰이더 — 패스 순서

**디더링은 반드시 마지막 패스여야 한다.** 왜곡보다 먼저 디더링하면 도트 격자가 뭉개져 지저분한 노이즈로 보인다. 도트는 항상 화면 픽셀 격자에 고정되고, 그 아래 이미지만 흐르는 것이 이 효과의 핵심이다.

| 패스 | 내용 |
|---|---|
| 1 | 배경 소스 렌더 → 렌더 타겟 |
| 2 | 마우스 속도장 축적 (핑퐁 FBO, 감쇠 + 노이즈) |
| 3 | UV 디스플레이스먼트 (유체 왜곡) |
| 4 | **베이어 8×8 오더드 디더링** — 화면 픽셀 좌표 기준 |

### 6.3 튜닝 상수

파일 상단 `CONFIG` 객체에 모아 한 곳에서 조절 가능하게 한다.

| 상수 | 기본값 | 범위 |
|---|---|---|
| `strength` | 0.06 | 0.02 (은은) ~ 0.15 (과격) |
| `decay` | 0.94 | 0.90 (짧음) ~ 0.98 (길게 남음) |
| `ditherScale` | 1.0 | 도트 크기 배율 |
| `levels` | 4 | 색 계조 단계 수 |

## 7. 성능 및 접근성

**모두 필수 항목이다.** 이 효과는 GPU 부하가 크고, 채용 담당자의 기기 사양을 통제할 수 없다.

| 항목 | 요구사항 |
|---|---|
| 픽셀 비율 | `devicePixelRatio`를 최대 1.5로 클램프 |
| 속도장 해상도 | 512×512 고정 (모바일 256×256) |
| 백그라운드 탭 | `document.hidden` 시 렌더 루프 정지 |
| 모션 민감 | `prefers-reduced-motion: reduce` → 왜곡 패스 비활성, 정적 디더 배경만 |
| WebGL 미지원 | 정적 배경 + 콘텐츠 정상 표시 (폴백) |
| 저사양 감지 | 초기 프레임 측정 후 60fps 미달 시 자동으로 효과 강도 하향 |
| 키보드 | 모든 카드·버튼·모달이 키보드로 조작 가능 |
| 스크린 리더 | 모달에 `role="dialog"`, `aria-modal`, 적절한 라벨 |
| 이미지 | 모든 이미지에 `alt` 제공 |

> **원칙: 배경 효과가 실패해도 콘텐츠 접근은 절대 막히지 않는다.**

## 8. 완료 기준

- [ ] 단일 HTML 파일을 브라우저에서 직접 열었을 때 정상 동작한다
- [ ] 인트로 → 리스트 → 모달 전체 흐름이 끊김 없이 이어진다
- [ ] `#/project/{slug}` 링크로 진입 시 해당 모달이 열린 상태로 뜬다
- [ ] 뒤로가기·`ESC`로 모달이 닫힌다
- [ ] JSON 배열에 객체 하나를 추가하면 카드가 자동 생성된다
- [ ] `prefers-reduced-motion` 환경에서 왜곡이 비활성화된다
- [ ] WebGL 비활성 환경에서 모든 콘텐츠가 읽힌다
- [ ] 모바일에서 레이아웃이 무너지지 않고 60fps에 근접한다
- [ ] 키보드만으로 전체 탐색이 가능하다
- [ ] 이메일 주소가 평문으로 소스에 노출되지 않는다

- CMS 연동 및 관리자 화면
- 다국어 지원 (v1은 국문 기준, 영문은 v2 검토)
