## 1. 디자인 원칙

이 세 가지가 충돌할 때의 우선순위이기도 하다. 위에서부터 이긴다.

### 1) 읽히는 것이 먼저다

배경 효과는 인상을 만들고, 콘텐츠는 판단을 만든다. 판단이 목적이다.
어떤 시각적 결정도 텍스트 가독성을 희생해서는 안 된다.

### 2) 절제해서 고급스럽다

레퍼런스로 삼은 사이트들이 고급스러워 보이는 이유는 화려해서가 아니라 **쓰는 요소가 적기 때문**이다.
색은 6단계 한 계열, 폰트는 2종, 모션은 한 성격. 여기서 늘리지 않는다.

### 3) 못 만들기 어려운 선택을 한다

작업자가 디자인 비전공자라는 전제를 설계에 반영한다.
미세한 감각 조정이 필요한 선택(세리프 이탤릭 조판, 자유로운 컬러 조합)을 피하고, **구조적으로 정돈되는 선택**(모노스페이스, 고정 팔레트, 8px 그리드)을 택한다.

---

## 2. 무드

**딥 플럼과 실버그레이의 대비. 어둡고 정밀하되 차갑지만은 않은 톤.**

의도적으로 피한 방향과 그 이유:

| 흔한 선택 | 피한 이유 |
|---|---|
| 검정 + 골드 | "고급"의 가장 전형적인 클리셰 |
| 오프화이트 + 남색 | 안전하지만 기억에 남지 않음 |
| 파스텔 홀로그램 | WebGL 스튜디오 씬에서 이미 포화 상태. 레퍼런스 출처가 드러남 |

딥 플럼은 검정만큼의 무게를 가지면서 흔하지 않고, 실버그레이가 채도를 눌러 촌스러워질 여지를 막는다. **디더링 질감 자체가 이미 희소성이므로 색은 한 방향으로만 민다.**

---

## 3. 컬러

### 3.1 팔레트

여섯 단계인 것은 셰이더 요구사항이다. 4단계는 색이 끊겨 8비트 게임처럼 보이고, 10단계를 넘으면 디더링 질감이 사라져 평범한 그라디언트가 된다.

| 이름 | HEX | 역할 |
|---|---|---|
| Void | `#150B17` | 페이지 배경, 최심부 |
| Deep plum | `#2E1430` | 카드·모달 면 |
| Plum | `#55234C` | 강조 면, 보더, 배지 배경 |
| Mauve | `#8A6F8C` | 보조 텍스트, 비활성 상태 |
| Silver | `#C9C4CC` | 본문 텍스트 |
| Light | `#EFECF1` | 제목, 최상위 강조 |

### 3.2 사용 규칙

- **Plum은 텍스트 색으로 쓰지 않는다.** 배경 대비가 부족하다. 면·보더·배지 배경 전용.
- **본문은 Silver, 제목은 Light.** 이 둘로 위계를 만들고 크기 차이는 최소화한다.
- **Mauve는 보조 정보에만.** 본문에 쓰면 읽기 힘들어진다.
- 팔레트 밖의 색을 추가하지 않는다. 링크·호버·활성 상태도 이 여섯 안에서 해결한다.
- 예외는 오류 상태 하나뿐 — 폼 검증 실패 등에서만 최소한의 경고색 허용.

### 3.3 대비 기준

| 조합 | 용도 | 요구 |
|---|---|---|
| Silver on Void | 본문 | WCAG AA 충족 |
| Light on Deep plum | 제목 | WCAG AA 충족 |
| Mauve on Void | 보조 | AA 미달 시 크기를 16px 이상으로 |

구현 후 실측 필수. **배경 셰이더가 텍스트 뒤에서 밝기를 흔들기 때문에**, 텍스트 영역 아래에는 Void 계열 반투명 레이어를 깔아 대비를 고정한다.

## 4. 타이포그래피

### 4.1 서체

| 용도 | 서체 | 비고 |
|---|---|---|
| 라틴 문자 전반 | IBM Plex Mono | 워드마크, 연도, 기술 태그, 역할 라벨, 버튼 |
| 한글 본문 | Pretendard | 프로젝트 설명, 소개문 |

**모노스페이스를 택한 이유**

1. 디더링은 픽셀 격자에 점을 찍는 기법이고, 모노스페이스는 글자를 균일한 칸에 넣는 서체다. 둘 다 격자에서 나오므로 배경과 글자가 같은 논리를 공유한다.
2. 글자 폭이 고정돼 있어 조판이 구조적으로 정돈된다. 감각적 미세 조정 없이도 무너지지 않는다.
3. 세리프 이탤릭 + 대형 산세리프 조합은 특정 스튜디오의 시그니처라 출처가 드러난다.

**한글을 모노스페이스로 쓰지 않는 이유**
한글은 모노스페이스에서 가독성이 크게 떨어지고, 완성도 있는 한글 모노 폰트 자체가 드물다.

### 4.2 스케일

| 용도 | 크기 | 굵기 | 행간 |
|---|---|---|---|
| 인트로 워드마크 | `clamp(40px, 8vw, 96px)` | 500 | 1.1 |
| 섹션 제목 | 24px | 500 | 1.3 |
| 카드 제목 | 18px | 500 | 1.4 |
| 본문 | 16px | 400 | 1.7 |
| 메타·캡션 | 14px | 400 | 1.5 |

**14px이 절대 하한이다.** 작은 글씨가 세련돼 보인다는 통념이 있으나, 읽는 사람이 눈을 찡그리는 순간 손해다. 채용 담당자의 연령대를 통제할 수 없다.

### 4.3 조판 규칙

- 모노스페이스 대문자에는 `letter-spacing: 0.08em`을 준다. 안 주면 답답해 보인다.
- 한글 본문에는 자간을 주지 않는다. `letter-spacing: 0`.
- 본문 한 줄 최대 길이 **70자** (`max-width: 42em`). 넘으면 눈이 다음 줄을 놓친다.
- 폰트는 2종을 넘지 않는다.

## 5. 레이아웃

- **8px 그리드.** 모든 여백은 8의 배수 (8 / 16 / 24 / 40 / 64).
- **여백을 아끼지 않는다.** 절제된 인상의 절반은 여백에서 나온다. 요소 간 최소 24px.
- 콘텐츠 최대 폭 1200px, 좌우 최소 여백 24px (모바일 16px).
- 카드 그리드는 `repeat(auto-fit, minmax(300px, 1fr))`.
- **프로젝트가 3개 미만이면 카드를 크게 키운다.** 빈약해 보이는 것을 막기 위한 장치.
- 모서리 반경은 4px로 통일. 둥근 모서리는 부드러운 인상을 주지만, 여기서는 정밀함이 우선이다.

## 6. 모션

### 6.1 원칙

> 사용자가 **가만히 있을 때 흐르는 것**은 느려도 된다.
> 사용자가 **무언가 누른 뒤의 반응**은 빨라야 한다.

느린 모션은 우아하지만 기다리게 만든다. 주 타겟이 채용 담당자이므로 이 대가를 UI에서는 치르지 않는다.

### 6.2 속도 규격

| 대상 | 시간 | 이징 |
|---|---|---|
| 클릭 후 첫 시각 반응 | **100ms 이내** | — |
| 버튼 호버 | 120ms | `ease-out` |
| 카드 호버 | 150ms | `ease-out` |
| 모달 열기·닫기 | 200ms | `cubic-bezier(0.2, 0, 0, 1)` |
| 인트로 → 리스트 전환 | 600ms | `expo.out` |
| 배경 왜곡 감쇠 | 1000~1500ms | 셰이더 내 감쇠 |

**100ms 기준의 근거**: 사람은 이 안에 변화가 있으면 즉각 반응했다고 인지한다. 모달이 200ms에 걸쳐 열려도, 눌린 순간 버튼이 반응하면 답답하게 느껴지지 않는다.

### 6.3 제약

- 이징은 위 표의 것만 사용. 바운스·오버슈트 계열 금지.
- 스크롤에 연동된 애니메이션은 배경 왜곡 강도까지만 허용. 요소 등장에는 쓰지 않는다.
- `prefers-reduced-motion: reduce` 시 배경 왜곡 정지, 전환은 페이드로 대체.

## 7. 배경 셰이더 비주얼 규격

### 7.1 소스

배경 이미지를 쓰지 않고 **절차적 그라디언트를 셰이더 내에서 생성**한다.
저작권 문제가 없고, 파일 크기가 늘지 않으며, 팔레트와 정확히 일치시킬 수 있다.

### 7.2 파라미터

| 상수 | 값 | 근거 |
|---|---|---|
| `levels` | 6 | 팔레트 단계 수와 일치 |
| `ditherScale` | 1.0 | 도트 = 화면 실제 1px 기준 |
| `strength` | 0.05 | 왜곡 기본 강도 |
| `decay` | 0.94 | 잔상 길이 |

**도트 크기가 이 디자인의 핵심이다.** 화면 실제 1픽셀에 가깝게 잡아야 멀리서는 매끄러운 그라디언트로, 가까이서는 격자로 보인다. 8비트 게임 같은 뭉텅이가 아니라 **필름 그레인에 가까운 질감**이 목표다.

`ditherScale`을 2 이상으로 올리면 레트로 게임 인상이 되어 고급스러움이 무너진다. **이 값은 함부로 올리지 않는다.**

### 7.3 텍스트 가독성 보호

셰이더는 밝기가 계속 변하므로 텍스트가 특정 순간 읽히지 않을 수 있다.

- 텍스트 블록 뒤에 Void 계열 반투명 레이어를 고정한다.
- 텍스트 영역에 해당하는 화면 구간은 셰이더 왜곡 강도를 50%로 낮춘다.

## 8. 이미지 처리

| 위치 | 처리 |
|---|---|
| 리스트 카드 썸네일 | 플럼 톤 디더링 적용 |
| 카드 호버 (데스크톱) | 디더 강도만 약화 — 원본 전환 아님 |
| 모달 내부 이미지 | **원본 컬러 그대로** |

**리스트와 모달의 목적이 다르다.** 리스트는 훑는 곳이라 통일감이 우선이고, 프로젝트마다 스크린샷의 색과 비율이 제각각이어도 한 톤으로 묶이면 정돈돼 보인다. 프로젝트 수가 적은 초기일수록 효과가 크다.

반면 모달은 검증하는 곳이다. 여기서까지 색을 덮으면 실무자가 실제 결과물의 색 감각을 판단할 수 없어, **자기 작업을 자기 필터로 가리는 셈**이 된다.

**주의**: 리스트 디더링을 과하게 걸면 무슨 작업인지 알아볼 수 없다. 형태는 남기고 색만 묶는 선에서 조정한다.

## 9. 금지 사항

### 9.1 시각 요소

- ✗ **이모지 일절 사용 금지** — 아이콘이 필요하면 단색 선형 아이콘만
- ✗ **이탤릭 사용 금지** — 한글은 이탤릭체가 존재하지 않아 브라우저가 강제로 기울이며 획이 뭉개진다
- ✗ **본문 14px 미만 금지**
- ✗ 팔레트 6색 외 컬러 추가
- ✗ 그림자, 글로우, 네온 효과
- ✗ 폰트 3종 이상 혼용
- ✗ 그라디언트 텍스트, 텍스트 아웃라인

### 9.2 콘텐츠

- ✗ **과장된 자기소개 금지** — "열정적인", "혁신적인" 등 근거 없는 형용사
- ✗ 검증 불가능한 성과 서술, 추정 수치를 결과로 제시하는 것
- ✗ 팀 프로젝트를 "우리는 ~했다"로만 서술 (기여도가 0으로 읽힌다)

실무자는 검증 가능한 것만 신뢰한다. 근거 없는 수식어는 중립이 아니라 **감점**이다.

### 9.3 인터랙션

- ✗ 스크롤 하이재킹
- ✗ 인트로를 건너뛸 수 없게 만드는 것
- ✗ 소리 자동 재생
- ✗ 바운스·오버슈트 이징

## 11. 적용 체크리스트

- [ ] 팔레트 6색 외의 색이 없다
- [ ] 본문이 16px, 최소 14px 이상이다
- [ ] 폰트가 2종을 넘지 않는다
- [ ] 이모지와 이탤릭이 없다
- [ ] 모든 여백이 8의 배수다
- [ ] 클릭 후 100ms 내에 시각 반응이 있다
- [ ] 배경 위 텍스트가 셰이더의 모든 순간에 읽힌다
- [ ] `prefers-reduced-motion`에서 왜곡이 멈춘다
- [ ] 자기소개에 근거 없는 형용사가 없다
- [ ] 모달 이미지가 원본 컬러다
